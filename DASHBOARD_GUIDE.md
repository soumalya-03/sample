# J&J Mentor KPI Dashboard: Demo Guide

## 1. What this dashboard is

This is a local demonstration built on the existing React + TypeScript frontend and FastAPI backend. It shows how an individual scorecard and process-work history could look when tied to a signed-in account. It is not a production J&J system and it is not connected to J&J systems of record, email, or identity services.

Everything displayed from the generated workbook is labeled **DEMO / SYNTHETIC DATA**. No real customer names, clinical records, or employee performance measurements are used.

## 2. Sign in

Open `http://localhost:8000/` while the local API server is running.

Use one of the two accounts seeded for the demonstration:

| Username | Password | Assigned dashboard |
| --- | --- | --- |
| `admin@local.dev` | `local-dev` | Role 09 – Operations Manager |
| `sales@local.dev` | `local-sales` | Role 14 – Sales Rep |

Choose the matching persona in the login form. The Category field is currently a demo selection only; it does not grant access or filter data. The server assigns the dashboard from the account, not from a role value supplied by the browser. Other persona choices are visible, but there are no demo accounts assigned to them.

A personal email or a newly registered account has no dashboard assignment. This demo does not use your personal mail password and does not authenticate through Google, Microsoft, or J&J corporate identity.

## 3. Dashboard views

The sidebar has four views:

- **Overview** shows request/process counts and weekly KPI trend charts.
- **Customer Metrics** shows the signed-in account's KPI scorecard, calculation description, reporting period, sample size, and definition source.
- **Alerts** lists illustrative SLA alerts and the request/process execution they refer to.
- **Workflows** groups the request's process executions in sequence. Expanding a process row in the execution table shows its task, execution ID, retry count, and any failure reason.

The execution table distinguishes completed duration from elapsed time for unfinished work. It does not assign a completed duration to an in-progress process.

## 4. Where the information comes from

### Supplied business workbook

`storage/Medical_Device_Business_Services_Inc_Mentor_08_09_2026.xlsx` supplies KPI names and formula/definition text from its role-specific sheets, including `Role 09 - Operations Mgr` and `Role 14 - Sales Rep`. The generator also reads the workbook's `Consulting Flows` sheet for the example order journey vocabulary. These are reference definitions; the source workbook does not provide observations for the two demo login accounts.

The existing application persona list remains intact. The supplied workbook has 16 role-specific sheets and some role names differ from the existing 17 frontend options, so the application does not infer assignments for the remaining roles.

### Generated synthetic workbook

`data/demo_process_kpi_data.xlsx` is generated by `backend/scripts/generate_demo_process_kpi_data.py`. It contains:

- 99 KPI definitions: role KPI names/formulas extracted from the supplied workbook, plus three illustrative process metrics.
- 56 synthetic weekly KPI measurements for the two assigned demo accounts.
- 12 synthetic requests, 50 process execution rows, and 14 example SLA alerts.
- Four example process stages: Capture Order, Validate Order, Submit Order, and Delivery.
- Two synthetic resource assignments: `admin@local.dev` and `sales@local.dev`.
- Separate sheets for requests, process master, activities/tasks, assignments, workflow definitions, executions, KPI definitions/measurements, alert rules/history, business outcomes, and a 134-field data dictionary.

The measurements are deliberately generated examples. Their numerator/denominator values, sample sizes, process statuses, timestamps, retry, durations, thresholds, and alert values are synthetic, not copied from the business workbook and not approved J&J targets. The sample process flow and SLA minutes are also illustrative.

## 5. How the dashboard values are calculated

The API loads the generated workbook and filters measurements and process executions by the signed-in account email. It does not use the frontend persona selector as authorization.

Role scorecard metrics are calculated from synthetic weekly inputs:

- Ratio percentage: `numerator / denominator * 100`.
- Average: `numerator / denominator`.
- Count: the recorded synthetic numerator.

Three illustrative process metrics are derived from that account's execution rows:

- **Process Completion Rate:** completed execution attempts divided by all execution attempts, multiplied by 100. Retries are separate attempts.
- **Average Completed Process Duration:** mean duration of completed executions only. In-progress rows are excluded; failed attempts are not counted as completed work.
- **On-Time Completion Rate:** completed executions at or below the example SLA divided by completed executions, multiplied by 100.

For an unfinished execution, elapsed minutes are calculated from its start time to the current time and shown separately. Example alerts are stored in the workbook and link to execution IDs. They represent a synthetic snapshot, not live alert monitoring.

Statistical control limits are not calculated or displayed. The source workbook does not supply a validated execution history suitable for that calculation, so the generated workbook explicitly leaves control-limit values unset. Example SLA thresholds are independent of control limits.

## 6. Start and refresh the demo

From the repository root, run the API:

```powershell
py -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000
```

To regenerate the synthetic workbook after editing the supplied source workbook:

```powershell
py backend/scripts/generate_demo_process_kpi_data.py
```

The current machine needs Node.js LTS and npm to rebuild the React frontend after frontend source changes:

```powershell
Set-Location frontend
npm install
npm run build
Set-Location ..
```

The current frontend bundle has been rebuilt and includes the four working sidebar views. After any future frontend source changes, run the build commands above and refresh the browser page to see them.

## 7. Important limitations

This is a demo data path, not durable process tracking. The workbook is a static generated snapshot; the app does not yet record real process events, provide a production assignment-management interface, or calculate validated business targets. Only the two demo account/persona assignments above are configured. Category/persona permissions, remaining persona assignments, production alert acknowledgement, external identity, and connections to enterprise systems require separate implementation and approval.

The share ZIP includes the generated demo workbook and built frontend, so the dashboard can run without the source workbooks. The environment's data-loss-prevention policy blocked adding the original supplied Excel files to the ZIP. Regenerating the demo workbook requires an approved copy of `Medical_Device_Business_Services_Inc_Mentor_08_09_2026.xlsx` at `storage/Medical_Device_Business_Services_Inc_Mentor_08_09_2026.xlsx`.
